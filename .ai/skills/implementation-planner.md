# implementation-planner

## Objetivo

Ordenar pasos de implementación para una sola tarea sin código aún.

## Cuándo usarlo

Tras task-planner; antes de editar archivos.

## Inputs requeridos

Tarea aceptada, rutas de código relevantes.

## Proceso

Orden: datos/contrato → backend → frontend → tests → docs.

## Output esperado

Lista numerada de pasos con riesgos por paso.

## Restricciones

No escribir código de producto en este paso.

## Checklist de calidad

- [ ] Dependencias entre pasos claras  
- [ ] Rollback mental por paso si aplica
