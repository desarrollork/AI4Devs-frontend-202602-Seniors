# spec-writer

## Objetivo

Convertir una idea en SPEC inicial acotada y revisable.

## Cuándo usarlo

Antes de cualquier implementación; cuando solo existe una idea vaga.

## Inputs requeridos

Contexto de negocio, usuario objetivo, restricciones conocidas, enlaces a `especificacion-inicial.md` si aplica.

## Proceso

1. Extraer problema y alcance MVP.  
2. Listar fuera de alcance.  
3. Criterios de aceptación globales medibles.  
4. Marcar TODO donde falte información.

## Output esperado

Borrador para `docs/PROJECT_SPEC.md` o feature-spec usando `.ai/templates/feature-spec-template.md`.

## Restricciones

No inventar requisitos no confirmados; usar TODO explícito.

## Checklist de calidad

- [ ] Alcance vs no alcance claros  
- [ ] Aceptación comprobable  
- [ ] TODO en huecos
