# Documentar cambio

## Objetivo

Sincronizar docs con comportamiento nuevo.

## Precondiciones

Feature merged o lista para merge; saber docs impactadas.

## Pasos

1. Identificar `README`, `docs/`, OpenAPI.  
2. Actualizar mínimo necesario; enlaces válidos.  
3. ADR si decisión nueva.

## Archivos afectados

Solo documentación acordada.

## Criterios de aceptación

Desarrollador nuevo puede ejecutar y entender cambio.

## Checklist final

- [ ] Comandos correctos  
- [ ] Sin duplicar novelas  

## Errores comunes

Docs genéricas sin reflejar el cambio real.

## Cuándo detenerse

No hay cambio observable — skip documentación.
